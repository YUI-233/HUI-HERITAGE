# HUI HERITAGE 正式环境发布手册

## 目标

本地 PostgreSQL 版本继续作为开发与完整业务验收环境。GPT Sites 正式环境使用
`HUI_DB`（D1）保存业务数据，使用 `HUI_MEDIA`（R2）保存图片、PDF 和上传文件。
代码、数据库结构和小型品牌静态资源随发布版本进入版本库；业务上传文件不进入 Git。

## 发布前置条件

发布一个完整业务版本前，必须同时满足：

1. 目标模块已经改为通过 D1/R2 运行，不再依赖 `DATABASE_URL`、`uploads/` 或运行时写入 `public/`。
2. 管理员、会员和审核权限已使用 GPT Sites 的已登录身份在服务端完成授权检查。
3. 相关 D1 迁移和媒体访问策略已验证；会员文件必须通过受保护的路由读取，不能给出公开对象地址。
4. `npm run build` 成功，并修复会阻止页面资源加载的警告。

在上述条件没有满足前，GPT 站只能作为展示/验收版本，不能作为本机业务系统的替代品。

## 数据与媒体迁移顺序

1. 先迁移公开的数字化遗产、馆藏、研究资料与站点设置，保证公众浏览、检索和详情页可用。
2. 再迁移管理员编辑、导入和审核记录，保留审核状态、理由和操作留痕。
3. 最后迁移会员、个人收藏、通知与受限媒体；迁移时保留用户所有权和媒体可见性。

每个阶段先从本机 PostgreSQL 导出经核对的数据，再导入 D1；R2 仅保存媒体字节，D1 保存媒体键、所有者、类型和可见性。

## 每周发布流程

1. 在 `http://localhost:3014` 完成本周改动，并验收相关页面与接口。
2. 执行 `npm run build`，确认正式托管构建通过。
3. 创建一个清晰的发布版本；不得将 `uploads/`、`output/`、构建产物或新的大文件媒体提交到发布源。
4. 保存并部署该版本到私有 GPT 正式站。
5. 在正式站复核本周涉及的流程。出现问题时，恢复到上一个已验证发布版本。

发布指令统一写为：`发布当前本地版本到 HUI HERITAGE 正式站，保持私有访问。`

## 当前私有试运行基线（2026-08-27）

- GPT 正式站：`https://huiheritage-digital-archive.minqiyusuf.chatgpt.site/`
- 访问范围：仅站点所有者，保持私有；不得在试运行结束前改为公开。
- 正式数据：6 条数字化遗产、180 条馆藏、3 条研究资料、26 项站点设置与 11 条媒体清单已进入 D1。
- 媒体状态：公开封面在 R2 未完成迁移时可回退到随站点发布的静态文件；受限 PDF 必须在所有者登录正式站后通过系统 Admin 媒体迁移接口进入 R2，不能改成公开静态链接。
- 首位系统 Admin：仅当正式环境配置邮箱与 GPT 登录邮箱一致，且 D1 尚无任何用户时自动建立；后续用户必须由 Admin 授权。

## 1–2 周试运行检查表

每天或每次发布后检查：首页、数字化遗产列表与详情、图书馆检索、研究列表与详情、登录后的账号中心、古籍文物新增/CSV 导入、图片上传、提交审核和他人审核。审核时必须验证同一账号不能审核自己的提交。

记录每个问题的发生时间、页面、操作、预期结果与实际结果。阻断首页、数据丢失、权限越权、受限媒体泄露的问题必须在绑定自定义域名前关闭；普通文案与样式问题可进入后续小版本。

试运行结束的放行条件：连续 7 天无阻断问题、至少完成一次完整的“新增 → 提交 → 他人审核 → 前台可见”闭环、R2 媒体清单全部完成、正式站错误日志无重复崩溃，并由站点所有者明确批准对外发布。

## 对外发布到 huiheritage.com

私有 GPT 正式站稳定测试 1–2 周后，经明确批准才进行：

1. 将站点访问策略改为公开。
2. 为 `huiheritage.com` 申请自定义域名绑定。
3. 在域名服务商后台填入系统返回的 DNS 验证、A 记录和/或 CNAME 记录。
4. 等待域名与 HTTPS 验证完成，检查根域名、`www` 跳转、关键页面和受限媒体。

`*.chatgpt.site` 地址继续保留为内部发布与验收入口。
